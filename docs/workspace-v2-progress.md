## Slice A — what was built

- `scripts/testmode.py`: `WORDICON_TEST_MODE=1` (inherited by children) installs a socket guard — outbound `connect`, `connect_ex`, `sendto` and name resolution are refused unless loopback on a port the guard was told about (`allow_port`, `WORDICON_TEST_ALLOW_PORTS`, `JOURNEY_PORT`); the real application's port (8420 / `PORT` / `WORDICON_TEST_DENY_PORTS`) is refused even when listed; every refusal is recorded in-process and appended to `WORDICON_TEST_EGRESS_LOG` with host, port and calling frames, never a payload. A provider gateway built in a test process gets an httpx transport that refuses every request (the attempt-loop checks need the real class). `harden(server)` swaps readers, Moira and speech for their stand-ins.
- `wordicon_cli.py` imports `testmode` before anything else and reads no `.env` in test mode (the real repository's `.env` only — the loader stays testable against a temp dir). `server.server_gateway()` answers the mock in test mode whatever the environment holds. `notify._configured()` is false in test mode.
- `scripts/state_root.py`: one data root per process — explicit argument, else `WORDICON_STATE`, else a root the process already chose by hand, else the repository's `local_state`; `apply()` rebases every `Path` attribute of every imported scripts module that points under the repository default or any previously applied root (no hand-kept list). `server.py` applies it at import, refuses the real store in test mode (`testmode.assert_isolated`) and prints the resolved root in its banner. The Vault drill's child process declares its own root before importing the server.
- `tests/journeys/run.sh` exports `WORDICON_TEST_MODE=1`, `WORDICON_STATE=$JOURNEY_STATE` and the egress log for every process of a run; `serve.py` sets the same before its first import and allows the mock producer's port.
- `tests/test_global_constraints.py` sets test mode and its scratch root before its first import, applies `state_root` on top of its hand list, and gains `_check_test_mode_fails_closed`: a direct socket to 1.1.1.1:443, a lookup of api.anthropic.com and a connection to the real port are refused and logged; with a sentinel key and model in the environment `server_gateway()` still answers the mock and a directly built provider gateway cannot send; notify stays off with sentinel mail credentials; the suite is not on the repository store and the server resolved the same root. Proven to fail under sabotage: `server_gateway` ignoring test mode → "answered 'anthropic'"; the guard's `connect` restored → "expected three refusals, saw 2".

Finding recorded during A (the instruction's warning was right): the first version of `state_root.apply()` took "the current cli.LOCAL_STATE" as the only old root. The journeys' seeder (`fixtures.py`) sets `cli.LOCAL_STATE` by hand and then imports the server; the server's `apply_from_env()` resolved to the repository default (no env set in that process) and rebased the seeder's scratch paths back onto the repository's own `local_state` — 70 fixture files landed in the container clone's real store before the journeys noticed an empty Home. Fixed by the resolution order above and by `run.sh` exporting the root and test mode for every process; with test mode on, that process would now refuse to run on the real store instead of writing to it. The container clone's `local_state` (gitignored, test exhaust) is the only thing that was written; the owner's Mac was never involved.

## Slice D — what was built

- `scripts/operations.py`: `operations.sqlite3` under the state root — `operations` (id, unique request key, action and registry version, proposal and snapshot ids, the fingerprint of the FULL execution request — action, registry version, snapshot, inputs, mode, lane, model, adapter — the configuration without secrets, status queued/claimed/running/complete/failed/unknown, local state, producer state, result reference, retry parent, last error, dispatcher, timestamps, legacy job id) and `operation_events` (ordered: reserved, claimed, resumed, stage, stage_intent/stage_end, attempt_intent/attempt_end, complete, failed, unknown, recover, reconciled, attempt_from). `reserve` (same key + same fingerprint → the same row; same key + changed fingerprint → 409), `claim` (one atomic queued→claimed UPDATE), `attach(gateway, op)` (the dispatch boundary on the gateway INSTANCE: every stage call and, in `Gateway._call_with_attempts`, every real HTTP attempt leaves its intent before it goes and its outcome after; a boundary that cannot be written sends nothing), `analyse`/`reconcile` (the six rows of the recovery table from persisted events and result files), `DispatcherLock` (fcntl on `operations.lock`; one dispatcher per store).
- `server.py`: the store is the authority and `JOBS` its projection — every job (legacy `/api/jobs` too, under `legacy:<job_id>` keys) is reserved, claimed and run by this process's dispatcher; `_update_job` mirrors progress, completion (with the result's ids) and failure; the job's gateway is attached before the first call; readers' gateways too. Routes: `POST /api/operations` (reserve, revalidate, dispatch), `GET /api/operations` (the record's recent operations with counts and the dispatcher's state), `GET /api/operations/<id>` (the store + the projection while it lives + the result files after a restart, with the recovery row), `GET …/events`, `POST …/recover` (reads and reconciles; sends nothing), `POST …/attempts` (a new operation under a new key linked to the first; refused while the first runs; refused by name when the plan — lane, model, registry version, adapter, action — changed, unless the new plan is confirmed; the cost said). `GET /api/jobs/<id>` answers from the store when the process no longer holds the job (unknown maps to a terminal failed with the honest sentence). Startup: `_ops_startup()` reconciles what a dead process left and resumes only what was provably never dispatched, under its unchanged plan (fingerprint equality), or says why it cannot.
- `scripts/wordicon_cli.py`: `Gateway.dispatch_hook`; `_write_exclusive` writes a temporary file and links it to the stable name (atomic, still refusing to overwrite).
- `webapp/work/results.js`: the Activity list loads the record's recent operations at boot ("From the record"); an unknown or failed card says what the record says (the recovery row, the count of dispatch intents) and offers "Check status / recover result" (sends nothing) and "Start another attempt" (a new key; a changed plan is shown and must be confirmed) as different doors; "Outcome unknown" never reads as running.
- `tests/journeys/fixtures.py` seeds two interrupted operations (one after its first dispatch intent, one never dispatched under a legacy key); `work.js` §12 sees them reconciled by the scratch server's startup; `_check_durable_operations` proves the flow, the boundary (a flaky gateway: intent/end per HTTP attempt; an unwritable store sends nothing), the four store-level windows, two REAL killed child processes (before dispatch → resumed by the survivor and completed with a `resumed` event; after the first intent → unknown and never resumed), and the second dispatcher's refusal.
- Not in D (carried): producer (investigation) operations use the same store from F with upstream ids and receipt states; cancellation appears only where a producer supports it (none yet).

## Slice E — what was built

- `scripts/workindex.py`: `work_index.sqlite3` under the state root — derived, rebuildable, excluded from the Vault. One item per top-level object with `store:kind:native` ids: writing (the notebook, the exact body, the native revision as version), runs (results/*.json, a file's size and mtime as the update signal, read from the file), receipt-only runs, inputs (inputs.jsonl by append offset), readers' readings (with each reader's answer), revision notes, concepts (with the count of rulings), saved words, questions, Library sources, recordings, Clinic rooms, investigation rooms, depositions, inquiries, recovery cases, operations (by the store's event sequence; the searchable text is the frozen snapshot's). Created and changed times kept apart. FTS5 over title/body/metadata with the user's words quoted as literal terms (no operator syntax reaches the engine), a LIKE fallback when FTS is absent or refuses; filters kind/tool/status/since/until/archived; stable paging by (changed_at, item_id). Generations: a rebuild writes into a new one and switches in one short transaction; a failed rebuild keeps the last working one. Health measures pending outbox rows and says "updating"/"incomplete" — a search is `exhaustive` only when neither holds. Archive is a ruling in `work_archive.jsonl` (append-only; the index reads it; nothing erased).
- `scripts/notebook.py`: `index_outbox` written in the save's own transaction; drained by the index (a crash between save and index is repaired; an index failure never touches a save). The operations store needs no outbox: its event sequence is the append log.
- `server.py`: `GET /api/work` (a bounded refresh first, then the search), `GET /api/work/<id>`, `POST /api/work/<id>/archive`, `POST /api/work/reindex`, `GET /api/work/health`; the serving process refreshes at startup and every 60 s.
- `webapp/work/yourwork.js`: search box, kind chips with counts from the index, since/archived filters, Rebuild, cards with the reopen action the item names (Open the document / the operation / the reading / the full result) and Archive; the health line says when search is updating; user text is rendered with textContent only.
- Tests: `_check_work_index` (yesterday's body found beyond the recent rows; twins distinct; a run and an input never linked to a document by text; the outbox drained and repaired after an unwritable index; hostile and malformed queries bound, never spliced, never a crash; generations; a partly failed rebuild reported incomplete; archive hides, keeps, survives a rebuild; routes through the gate; no innerHTML); `work.js` §10.
